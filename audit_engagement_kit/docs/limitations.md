### 4.1 使用提醒

- **不要**把 `firm_notice`（拟聘）等同于实际审计机构，学术使用以 `firm_official` 为准；
- 面板去重规则是「变更 > 续聘 > 聘任，同期取最早」，与明细的行数差异属预期；
- 前任事务所、连续服务年限、审计收费是公告自愿披露字段，缺失率高，不宜作为主变量；
- 时间节点是**公告披露值**，不是人事档案；同一人跨公告可能给出略有差异的年份，
  跨公告回填只补空缺、不改已有值；
- 姓名校验的目标是「可复核」，不保证 100% 无错；研究使用前建议用核对样本抽检。

## 5. 改进方向

1. **单角色缺失攻坚**：1611 份缺项目合伙人、1360 份缺复核人，多为 2020–2021 年
   披露方式差异（只写「拟任签字注册会计师」、复核人写「待定」），可按模板逐类补规则；
2. **扩展变量**：同一批表格还包含「近三年签署/复核家数」「是否兼职」「执业资质」
   「何时开始从事复核工作」，可复用现有版面引擎扩展；
3. **面板宽表**：以「公司-审计年度」为主键输出 Stata 可读的 `.dta`；
4. **OCR 覆盖参数化**：把 `ocr` 的筛选条件（标题、页数上限、文本长度阈值）做成参数，
   用于后续增量公告；
5. **噪声清理**：原始 PDF 缓存（约 12 GB）可清理后按公告 ID 重建；切片文本可从
   原始 PDF 重新切片恢复，`v2_results.jsonl` 可由 `extract` 重跑生成。

## 6. 质量指标如何复现

```bash
# 指标快照：公告数、角色覆盖、节点覆盖、按披露年齐全率、P=R 疑点数
python -m audit_kit stats

# 缺漏盘点：无人员公告分类、角色缺失分布、节点来源分布、元字段空缺
python -m audit_kit gaps

# 重新导出 Excel（「统计」工作表会写入同类指标）
python -m audit_kit export

# 重新生成 300 条人工核对样本（含疑点清单）
python -m audit_kit sample
```

指标口径定义见 [data-source](data-source.md)，字段定义见
[data-model](data-model.md)。
