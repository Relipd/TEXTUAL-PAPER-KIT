# 抽取方法

本文说明如何从一份聘任公告 PDF 中得到「职位 / 姓名 / 四个时间节点」。整体是
**规则 + 版面坐标**的确定性流水线，不调用任何大模型，同一份 PDF 每次运行结果一致
（`demo` 与测试即以此为前提）。

## 1. 为什么不用纯文本正则

公告的「(二) 项目信息」大多是多列表格。PDF 的文本流按阅读顺序把表格拆散，
常见两种破坏：

1. **名字被拆行**：单元格内换行，`邵建克` 在文本流里成了 `邵建\n克`；
2. **标签被拆行**：窄列换行，`项目合伙人` 成了 `项目合\n伙人`。

若直接对文本流做「角色标签后取 2–4 个汉字」的正则，会命中窗口里第一个看起来像姓名的
词，把「时间」「家次」「能力」「经验」当成姓名，也会把证券简称（如「宏润建设」）
或公司名当成项目组成员。文本抽取通道仅作为版面通道失败后的兜底，且必须配合严格的
姓名校验。

## 2. 总体流程

```
PDF ──► 版面重建 ──► 角色定位 ──► 分版式取姓名 ──► 姓名四重校验
                                                    │
              ┌─────────────────────────────────────┘
              ▼
        时间节点对齐（表格坐标 / 叙述式正则）
              │
              ▼
        兜底链：版面 → 叙述 → 文本流 → 项目信息段落锚点
              │
              ▼
        回填：姓名锚定上下文 → 同公司跨公告补齐（正式公告优先）
              │
              ▼
        去重 + 角色人数上限 → {职位: [姓名], 人员时间节点}
```

## 3. 版面重建：把页面变成「视觉行 → 单元格」

`page_rows(page)` 用 PyMuPDF 的 `get_text("words")` 拿到每个词的坐标，再按坐标聚类：

1. 以全页词高的中位数 `h` 作为基准，纵向容差取 `max(2.5, 0.55h)`；
2. 按纵向中心把词聚成**视觉行**（同一表格行内即使字略有高低也能归为一行）；
3. 行内按 `x0` 排序，相邻词的横向间距 `≤ max(6.0, 0.9h)` 时合并为同一**单元格**，
   否则切成新单元格。

得到的结构是：

```python
{"y": 行中心纵坐标, "cells": [(x0, x1, 文本), ...], "h": 字高}
```

它把「同一单元格内换行」和「相邻单元格」区分开，是后续所有版式判断的基础。

### 3.1 跨行拆字的两种情形

| 情形 | 表现 | 判别方法 |
|---|---|---|
| 同一姓名的续字 | 单元格内换行，`邵建` / `克` | 续字 `x0` 比首字右移约半个字宽（居中换行） |
| 下一行另一个人 | `张伟` / `李娜` 上下两行 | 两行姓名 `x0` 完全对齐 |

`_first_column_names` 先按「同一视觉带内、与首列 x0 几乎对齐」取候选，再对 2 字姓名
检查其下方是否有「右移半个字宽的单字」用于补全。角色标签的跨行拼合同理，见下一节。

## 4. 角色定位

`_find_role_cells(rows)` 扫描每个单元格，匹配三类角色标签，并对被换行拆开的标签做
跨行（向下 1–2 行）拼合（如 `审计项目合` + `伙人`、`拟签字注册` + `会计师`、
`质量控制复` + `核人`）。匹配条件限定在单元格文本的开头附近，避免把正文句子里的
「项目合伙人」误当表头。

支持的标签写法（节选）：

| 角色 | 兼容写法 |
|---|---|
| 项目合伙人 | 项目合伙人、拟签字项目合伙人、审计项目合伙人、签字项目合伙人 |
| 签字注册会计师 | 签字注册会计师、拟签字注册会计师、签字会计师、项目签字注册会计师、第一/第二/第三签字注册会计师 |
| 质量控制复核人 | 项目质量控制复核人、项目质量复核人员、质量控制复核人、项目质量复核人、质量复核人、项目质量控制负责人、项目质量控制复核合伙人、独立复核合伙人、复核合伙人 |

## 5. 四种版式

| 版式 | 识别特征 | 取名方式 | 典型来源标签 |
|---|---|---|---|
| **R 行式表格** | 角色在左、姓名在右，右侧数列为四个年份 | 取角色标签右侧最左的中文列；签字注册会计师可有多名，按从上到下顺序；合伙人与复核人各取离标签纵向中心最近的一名 | `table` |
| **T 田字表格** | 首行为角色（表头），首列为「姓名」等行标签 | 找到「姓名」行，按列 x 坐标把姓名映射到表头角色；时间节点取各角色列下方的连续年份行 | `table_t` |
| **P 叙述式** | 「项目合伙人：张三先生，2012 年成为注册会计师……」 | 角色标签后取第一个通过校验的 2–4 字姓名；描述段用四组正则取时间节点 | `prose` |
| **C 合称式** | 「项目合伙人及签字注册会计师 1：王璟」 | 同一人同时登记为项目合伙人与签字注册会计师 | `prose` |

另外两类文本写法也有专门处理：

- **姓名在职务之前**：「李进华项目合伙人」「合伙人刘志坚拟担任项目质量控制复核人」
  「项目合伙人由张三担任」；
- **同一单元格内「姓名 + 职务」连写**：取角色标签左侧文本或同一单元格内标签前缀。

表格版式优先于文本版式：只有版面通道完全取不到人员时，才启用整页文本通道。

## 6. 姓名四重校验

为过滤上述误判，每个候选姓名都要通过 `valid_name`：

| 校验 | 内容 | 目的 |
|---|---|---|
| 1. 姓氏白名单 | 常用单姓 + 复姓（欧阳、司马、上官……）+ 从语料首字频次补充的稀姓 | 保证是真实姓氏；姓名须为 2–4 个汉字 |
| 2. 停用词 | 时间、家次、经验、能力、年度、信息、姓名、会计师、事务所…… | 排除表格/正文里的普通词 |
| 3. 上市公司简称黑名单 | 运行前注入全部证券简称（`set_co_names`） | 避免把「宏润建设」这类简称当人名 |
| 4. 否定式上下文 | 角色标签后紧跟「近三年」「未因」「不存在」「均未」等 | 「近三年未因执业行为受处罚」不能当姓名 |

此外还有尾部噪声清理：`clean_name_tail` 会去掉「程峰近三」这类粘连在姓名后的普通词；
同一公告内按 `(角色, 姓名)` 去重，并设角色人数上限
（项目合伙人 ≤2、签字注册会计师 ≤4、质量控制复核人 ≤1），防止串列产生异常多值。

## 7. 时间节点对齐

| 版式 | 方法 |
|---|---|
| 行式表格 | 以姓名单元格右边界为起点，取同一视觉带内的纯年份单元格；按表头列 x 中心对齐（偏差 ≤80px）；表头只识别出部分列时，剩余列按标准顺序兜底补位 |
| 田字表格 | 姓名行下方连续的「一年一格」取值行，按标准四行顺序 `[成为注会, 从事上市审计, 本所执业, 本公司服务]` 逐行取与角色列对齐的年份 |
| 叙述式 | 四组正则分别匹配「X 年成为注册会计师」「X 年开始从事上市公司审计」「X 年开始在本所执业」「X 年开始为本公司提供审计服务」 |
| 表头识别 | 兼容「何时成为注册会计师」「开始从事上市公司审计时间」「在本所执业时间」「何时开始为本公司提供审计服务」等表头写法，也兼容表头跨行拆字 |

只接受形如 `2012`、`2012 年`、`2012-03`、`2012 年 3 月` 的**纯年份单元格**，
不做跨列推断；原文不写月份则只保留年份。

## 8. 兜底链

抽取按「只补缺失角色 / 只补缺失节点」逐级降级，不会用低置信结果覆盖高置信结果：

| 级别 | 通道 | 触发条件 | 产出 |
|---|---|---|---|
| 1 | 版面（`layout`） | 页面上能找到角色标签 | 人员 + 时间节点 |
| 2 | 叙述式（`prose`） | 版面通道没有取到任何人员 | 人员 + 叙述式节点 |
| 3 | 文本流（`rawtext`） | 叙述式也没有取到人员 | 只取姓名（合并叙述/合称/倒装/姓名在前四种文本策略） |
| 4 | 项目信息段落锚点（`secfallback`） | 仍有角色缺失 | 只在「(二)项目信息」段落内，以角色标签为锚点取姓名；先截到下一个人物标签，避免串行 |
| 5 | 姓名锚定上下文（`+ctx`） | 人员有了但节点缺失 | 在全文中以该姓名为中心取前后 240 字，再跑一遍叙述式正则 |
| 6 | 跨公告回填（`+bf`） | 仍缺节点 | 用同一公司其它公告中同名人员的记录补齐，正式公告优先 |

补充规则：

- 签字注册会计师应包含项目合伙人本人。若公告只列了项目合伙人、没有单列签字人，
  则把合伙人同时登记为签字注册会计师，来源标记加 `(*)`、`concurrent=1`；
- 兜底通道只补角色、不给节点；节点依赖第 5、6 级回填，因此兜底通道的四节点齐全率
  明显低于表格通道（见第 10 节）。

## 9. 三处针对数据源的专项处理

| 机制 | 解决什么 | 处理方式 | 本地全量运行结果（参考） |
|---|---|---|---|
| **同名公告撞名修复** | 同公司同年同标题的多份公告（原公告与更正版、承诺函等）切片文件名相同，后一份的 `pdf/txt` 指向前一份，导致「拿错文件」 | 按 `announcementId` 从原始 PDF 重新切片，文件名追加 `-{aid}` 保证唯一，再重新抽取并回写 | 修复 315 份 |
| **正式公告优先** | 同一事项有正式公告 + 独立意见 / 承诺函 / 陈述意见，非正式文件缺人员或节点 | 删除非正式文件中与正式公告重复的人员；缺节点时用同公司同名记录跨公告回填（正式公告优先） | 删除重复人员 67 条；回填 15337 条人员的时间节点 |
| **扫描件 OCR** | 无文字层的公告无法抽取 | 候选按「`src='scan'` 或文本 <50 字」+ 标题属聘任类 + 页数 ≤60 过滤，只送前 12 页；OCRmyPDF（Tesseract + chi_sim）补文字层后按同一套版面逻辑重抽，`src` 记为 `ocr` | 41 份候选，13 份恢复出人员 |

OCR 细节：依赖 `ocrmypdf` 与 Tesseract 中文语言包（推荐 `tessdata_best` 的
`chi_sim.traineddata`）；若仓库内存在 `ocr/tessdata` 则通过 `TESSDATA_PREFIX`
指定，否则使用系统 Tesseract 语言包。OCRmyPDF 默认依赖 Ghostscript，可用
`--output-type pdf --optimize 0` 走内置后端规避。

## 10. 各通道的实际质量

本地全量运行的「四节点齐全率」（人员有时间节点 / 该通道人员数）：

| 抽取通道 | 四节点齐全率 | 说明 |
|---|---|---|
| 田字表格 `table_t` | 90% | 表头-列对齐，节点最完整 |
| 行式表格 `table` | 71% | 姓名右侧年份列，偶有缺列 |
| 段落叙述 `prose` | 52% | 叙述中未必写全四个节点 |
| 段落兜底 `secfallback` / 文本流 `text` | 36% | 只取姓名，节点靠上下文与跨公告回填 |

整体人员四节点齐全率为 66.6%，公告级「三字段齐全率」为 88.2%。质量指标与已知
问题见 [limitations](limitations.md)。

## 11. 输出与可复核性

单份公告的抽取结果形如：

```json
{
  "roles": {
    "项目合伙人": ["杨誉民"],
    "签字注册会计师": ["许湘照"],
    "质量控制复核人": ["黄天义"]
  },
  "persons": [
    {
      "role": "项目合伙人",
      "name": "杨誉民",
      "times": {"become_cpa": "2007", "start_listed": "2004",
                "start_firm": "", "start_company": ""},
      "source": "prose+ctx"
    }
  ],
  "src": "prose",
  "note": ""
}
```

- 公告级 `src` 记录命中的通道集合，多通道命中时以 `+` 连接（如 `layout+prose`）；
- 人员级 `source` 记录该人的姓名/节点来源，落到库中即 `persons.time_src`；
- 每个姓名都能回溯到切片文本，可用 `sample` 命令生成「原文片段 + 疑点标记」的人工
  核对样本；字段取值见 [data-model](data-model.md)。

> `samples/expected/` 中的黄金结果由基线版本（baseline, v0.1.0）生成，作为回归基线；
> 若抽取逻辑有意升级，需要同步重新生成黄金结果，并在提交说明中解释差异。
